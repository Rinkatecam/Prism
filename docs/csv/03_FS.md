## How to read this document

Each functional item is identified by **FS-NNN**. Each one lists:
- **Implements**: URS-IDs it satisfies (one FS may satisfy many URS items)
- **Implementation**: module / file / function path
- **Inputs / outputs / errors**: contract
- **Verification**: pointer to the test(s) that exercise it (full mapping in `10_TRACEABILITY_MATRIX.md`)

Numbering groups parallel the URS document.

## A. Monitoring & dashboard

### FS-001 — Per-server metric collection
- **Implements**: URS-001
- **Implementation**: `collector_v2/supervisor.py` (scheduler) → `collector_v2/workers.py` (executor) → `collector_v2/checks.py:check_metrics` → `collector_v2/scripts.py:PS_COLLECT_SCRIPT` (PowerShell payload) → `collector_v2/aggregator.py:_handle_metrics_result` (persistence).
- **Cadence**: `DEFAULT_INTERVALS_S[CheckType.METRICS] = 60 s`; configurable via `settings.poll_interval_seconds`. Per-server hash-shard stagger avoids thundering herd.
- **Output**: row in `metrics` table; in-memory `state.latest_by_server[name]` for dashboard fast-read.
- **Error paths**: WinRM offline → `Result.error_kind='offline'`, aggregator preserves previous metric payload but marks status. Timeout → `Result.error_kind='timeout'`.
- **Verification**: `test_collector_v2_supervisor.py`, `test_collector_v2_workers.py`, `test_collector_v2_aggregator.py::test_metrics_*`.

### FS-002 — Status classification (threshold layer)
- **Implements**: URS-002
- **Implementation**: `detection.py:compute_status(metrics, thresholds, server_name, settings)` returns one of `{healthy, warning, critical, offline}`.
- **Inputs**: parsed metric dict; per-server thresholds (overridable by maintenance window via `maintenance.py:_get_maintenance_thresholds`).
- **Output**: status string.
- **Verification**: indirectly exercised by `test_collector_v2_aggregator.py` (status transitions). **GAP — no direct unit tests for `compute_status` — see `17_FINDINGS_AND_GAPS.md` finding F-002.**

### FS-003 — CPU N-of-M smoothing gate
- **Implements**: URS-003
- **Implementation**: `detection.py:_cpu_gate_record + _cpu_gate_passes`. Per-server ring deque in `_cpu_warn_history[server_name]`.
- **Configuration**: `anomaly_detection.cpu_warning_window_cycles` (M, default 5), `anomaly_detection.cpu_warning_consecutive_cycles` (N, default 3).
- **Behaviour**: a warning-only CPU breach is suppressed unless N of the last M samples were also above warning. Critical-class breaches bypass the gate.
- **Verification**: indirectly via `test_collector_v2_aggregator.py`; **GAP — direct tests for the ring would harden this control.**

### FS-004 — Maintenance window evaluation
- **Implements**: URS-004
- **Implementation**: `maintenance.py:_get_active_maintenance_window(server_name, settings)` returns the active window dict or `None`. Drives both threshold loosening (via `_get_maintenance_thresholds`) and full alert suppression (via `_is_alert_suppressed_by_maintenance`).
- **Inputs**: settings; current wallclock in `settings.timezone` (refuses naive datetime).
- **Output**: `dict | None`.
- **Verification**: **GAP — no direct tests of `_get_active_maintenance_window` — see finding F-004.**

- **Verification**: covered indirectly by ad-hoc DB tests; **GAP — no direct test that confirms a given retention setting deletes the expected rows from each table.**

### FS-033 — Windows-update install
- **Implements**: URS-033
- **Implementation**: `routes/api/updates.py:/api/servers/<n>/install-updates` schedules a Windows scheduled task on the target running an `-EncodedCommand` PowerShell payload (`_wu_ps_script_body`); the target writes `C:\ProgramData\Prism\update-status.json` as it progresses.

- **Verification**: indirectly via `test_install_state_lifecycle.py`.

### FS-035 — Cancel install

### FS-036 — Live update status

### FS-037 — Auto-clear stale install_state
