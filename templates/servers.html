{{ t.server_setup_guide }}

1
{{ t.step_enable_winrm }}

RDP into the server and open an {{ t.step_elevated_ps }} (Run as Administrator):

winrm quickconfig -force

This enables the WinRM service and opens the firewall for port 5985 (HTTP).

2
{{ t.step_verify_winrm }}

Still on the target server, check the listener configuration:

winrm enumerate winrm/config/listener

You should see Transport = HTTP and Port = 5985.

3
{{ t.step_check_auth }}

On the target server, verify Negotiate or Kerberos is enabled:

winrm get winrm/config/service/auth

Ensure Negotiate = true or Kerberos = true is shown.

4
{{ t.step_test_connectivity }}

On the Prism host, open PowerShell and test the connection:

Test-WSMan -ComputerName SERVER.DOMAIN.COM

If this fails, check firewall rules and DNS resolution. Use the FQDN, not the IP address.

5
{{ t.step_add_server }}

Click "Add Server" and fill in the fields:

  • Name — Display name (e.g. FileServer-01)
  • Host — Use the FQDN (e.g. SERVER.AD.DOMAIN.COM), not the IP
  • Username — Domain format: DOMAIN\username (e.g. EXAMPLE\Administrator)
  • Password — The account password (stored encrypted)
  • Port — Default 5985 for HTTP
6
{{ t.step_test_connection }}

Click the "Test Connection" button in the modal or the icon in the server table. You should see a green success message with the server hostname.

{{ t.get('troubleshooting', 'Troubleshooting') }}
{{ t.troubleshoot_timeout }} — Check that port 5985 is open in Windows Firewall on the target. Run Get-NetFirewallRule -Name "WINRM*" to verify.
{{ t.troubleshoot_auth_failed }} — Verify the username format is DOMAIN\user. Test with PowerShell first: 
$cred = Get-Credential
Invoke-Command -ComputerName SERVER.DOMAIN.COM -Credential $cred -ScriptBlock { $env:COMPUTERNAME }
{{ t.troubleshoot_host_not_found }} — Use the FQDN instead of the IP. Kerberos authentication requires the full domain name to work properly.
{{ t.troubleshoot_access_denied }} — The account needs WinRM access. Add it to the Remote Management Users group on the target server, or use a domain admin account.
