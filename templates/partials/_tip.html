What each one is for: tip(desc_key, desc_fallback, ...) STANDALONE trigger: sr-only mirror + button together, because the two must never come apart (§5.3). tip_button(desc_key, desc_fallback, tip_id, ...) the button ALONE, for a heading — see tip_mirror. tip_mirror(desc_key, desc_fallback, tip_id) the sr-only span alone, by id. tip_overflow(text, extra_class='') text that is ALREADY visible and clipped: no mirror, no describedby (§5.3 — a trigger with visible text gets aria-describedby only, and here there is nothing ELSE to describe it with). BINDALL NEEDS data-tip-title PRESENT, EVEN EMPTY. base.html's `bindAll()` finds carriers with `document.querySelectorAll( '[data-tip-title]')` — an attribute-PRESENCE selector, not a truthiness check. tip_overflow() has no title, but it still renders `data-tip-title=""` for exactly this reason: omit the attribute and the element is invisible to bindAll, gets no listeners at all, and never opens on any input method — even though data-tip-desc is sitting right there on it. `show(e)` separately bails when BOTH title and desc read empty (`if (!title && !desc) return`), which guards a different case (a re-enabled control whose reason was just cleared) and does not excuse dropping data-tip-title from the markup here. `.ps-tip` on a button is read by base.html's onPointerDown: a real button already delivers a `click` from a tap, so long-press setup is skipped for anything carrying that class (see the state-machine comment above bindAll in base.html). `.ps-tip-overflow` is the matching marker for the OTHER kind of carrier, so tests/test_design_tooltip.py (T-4, step 6) can exempt it from "every carrier has a mirror" without a tag-name check.
