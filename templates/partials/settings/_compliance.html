{# ── Compliance (CSV / GAMP 5) ────────────────────────────────────────── WP-4 D6. The module has exactly one setting, `compliance.enabled`, and until now it had NO surface at all: the only way to turn it on was to hand-edit config.json and restart. A feature flag with no control is not a deliberate design, it is a gap — and this one gates a regulated module, so the people most likely to need it are the least likely to be editing JSON on a server. URS-204 pins what "off" means: the nav item is hidden, the view routes 404, the API endpoints 404. All three still hold — this adds a control for the flag, not an exception to it. `sop_log` survives either way, which is URS-204's other half: toggling the flag changes the UI surface and never the evidence. The toggle is in the `general-input` bucket, not `security-input`: it changes routing and navigation, which a reload picks up. It does not touch the collector, so it does not raise the restart badge. #}
