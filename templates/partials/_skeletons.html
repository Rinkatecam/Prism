{# ── Skeleton shapes — the ghost of what is coming ────────────────────── `.skeleton` / `.skeleton-text` / `.data-settled` landed in app.css last round with ZERO carriers in any template. This file is the carrier. It exists as macros rather than inline blobs so that a region's ghost and its real markup can be compared side by side, and so there is ONE place to change when a partial's layout moves. Two things about the CSS that are easy to get wrong: 1. `.skeleton-text` sets ONLY `height`/`margin`. The background and the sweep live on `.skeleton`. A bare `class="skeleton-text"` is an invisible 0.75em box — always pair them. 2. `.skeleton-text:last-child { width: 60% }` is (0,2,0) and beats a Tailwind `w-*` utility (0,1,0), so the ragged last line cannot be overridden from the markup. Where an exact width is wanted, use `.skeleton` with `h-*`/`w-*` and leave `.skeleton-text` out — those utilities are (0,1,0) against `.skeleton`'s own (0,1,0) and Tailwind's sheet is injected later, so they win. Mixing the two fights itself. Sizes below are MEASURED off the rendered partial, not read off the source.
